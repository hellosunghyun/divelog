# divelog.page 웹디자인 가이드라인
## Quiet Depth Design Guidelines

---

## 1. 디자인 목표

`divelog.page`의 디자인은 "예쁜 바다 사이트"가 아니라,  
**Learner의 질문과 기록이 조용하고 깊게 읽히는 공간**을 만드는 데 목적이 있다.

이 제품이 전달해야 하는 인상은 다음과 같다.

- 조용하다
- 깊이가 있다
- 따뜻하지만 가볍지 않다
- 과장되지 않지만 분명한 개성이 있다
- 기록과 질문이 주인공이다
- 결과보다 과정이 먼저 보인다
- 기술 서비스이지만 인간적인 온도가 있다

이 사이트는 화려한 연출보다 **명확한 구조, 정제된 타이포그래피, 안정적인 간격, 낮은 시각적 소음**으로 고급스러움을 만든다.

---

## 2. 핵심 디자인 철학

### 2.1 Content-first
인터페이스는 기록을 돋보이게 해야 한다.  
배경, 애니메이션, 그래픽은 분위기를 만들기 위한 보조 장치일 뿐, 기록보다 앞에 서면 안 된다.

### 2.2 Journey-first
이 사이트는 피드가 아니라 여정이다.  
따라서 모든 핵심 화면은 "무엇이 최신인가"보다 "지금 어디를 지나고 있는가"를 먼저 보여줘야 한다.

### 2.3 Quiet Depth
깊이감은 강한 그림자나 3D 효과로 만들지 않는다.  
얇은 경계선, 부드러운 surface 레이어, 채도 낮은 블루 계열, 충분한 여백으로 만든다.

### 2.4 Reflection over Stimulation
SNS처럼 즉각적인 반응과 강한 자극을 만들지 않는다.  
대신 읽고, 머물고, 다시 생각하게 만드는 구조를 지향한다.

### 2.5 Belonging without Competition
사람을 연결하되, 비교하게 만들지 않는다.  
지표를 전면에 세우지 않고, 질문과 공명을 중심에 둔다.

---

## 3. 시각적 북극성

이 제품의 시각적 북극성은 아래 세 가지다.

### 3.1 에디토리얼
카드가 많더라도 전체 인상은 "콘텐츠 플랫폼"이어야 한다.  
정보가 많아도 차분하고, 글이 잘 읽혀야 한다.

### 3.2 수면 아래의 깊이감
해저 감성은 직접적인 물고기, 버블, 잠수부 그래픽이 아니라  
**빛이 낮게 깔린 푸른 공간, 수심이 내려가는 색감, 레이어가 겹치는 질감**으로 전달한다.

### 3.3 정제된 현대성
복고풍이나 장난스러운 느낌보다  
**깨끗한 구조, 선명한 위계, 제한된 색 사용, 정밀한 간격**으로 현대성을 만든다.

## 5. 레이아웃 시스템

### 5.1 전체 구조
레이아웃은 항상 아래 우선순위를 따른다.

- 상단 글로벌 네비게이션
- 현재 문맥을 보여주는 헤더 또는 Hero
- 핵심 콘텐츠
- 보조 콘텐츠
- 하단 행동 유도 또는 푸터

### 5.2 컨테이너 폭
권장 폭은 아래와 같다.

- 전체 캔버스 최대 폭: `1440px`
- 콘텐츠 최대 폭: `1200px`
- 읽기 중심 상세 폭: `720px`
- 보조 레일: `280 ~ 320px`

### 5.3 컬럼 시스템
- 모바일: 1열
- 태블릿: 1열 우선, 일부 2열
- 데스크톱: 12-column grid
- 상세 본문은 grid 안에 있어도 읽기 폭은 별도로 제한

### 5.4 섹션 간 간격
섹션 간 vertical rhythm은 크게 잡는다.

권장:
- 모바일: `48 ~ 64px`
- 데스크톱: `80 ~ 120px`

### 5.5 정렬 원칙
- 같은 계층의 카드와 텍스트는 baseline이 맞아야 한다.
- 불필요하게 centered layout를 남발하지 않는다.
- Hero 이후 섹션은 왼쪽 정렬을 기본으로 한다.
- 카드 내부의 정렬 규칙은 철저히 통일한다.

## 6. 공간과 간격

### 6.1 spacing scale
기본 spacing scale은 4의 배수로 통일한다.

권장 단계:
- 4
- 8
- 12
- 16
- 24
- 32
- 40
- 48
- 64
- 80
- 96

### 6.2 여백 우선순위
- 페이지 외곽 여백
- 섹션 간 여백
- 카드 내부 패딩
- 요소 간 여백

이 순서로 관리한다.  
카드 안이 답답한데 섹션만 넓은 식의 불균형을 만들지 않는다.

### 6.3 고급스러움의 핵심
고급스러움은 장식이 아니라 **넉넉한 여백과 통일된 간격**에서 온다.  
특히 질문 카드와 기록 본문 주변에는 일반 카드보다 여유 있는 breathing space를 둔다.

---

## 7. 색상 시스템

### 7.1 기본 원칙
색은 많을수록 풍부해지는 게 아니다.  
이 사이트는 적은 수의 색을 깊이 있게 써야 한다.

### 7.2 Core Palette
- Background: `#F6F8FB`
- Surface: `#FFFFFF`
- Surface Secondary: `#F2F5F8`
- Border: `#E3E8EF`

- Text Primary: `#1D1D1F`
- Text Secondary: `#6E6E73`
- Text Tertiary: `#8C8C91`

- Deep Ocean: `#0B2447`
- Ocean Blue: `#146C94`
- Reef Cyan: `#6CC4D6`
- Mist Blue: `#EAF4FA`

### 7.3 Stage Tone Mapping
Stage의 성격을 색으로 가볍게 암시한다.

- Prelude: Mist 중심
- Bridge: Cyan 중심
- Challenge: Deep Ocean 중심
- Epilogue: Mist + Neutral 중심

### 7.4 색 사용 규칙
- 본문은 항상 높은 대비의 중립 텍스트 사용
- 강조는 컬러보다 weight와 spacing으로 먼저 해결
- 상태색은 semantic 목적에만 사용
- 카드마다 다른 accent color를 남발하지 않음
- 링크는 텍스트처럼 보이되 hover/active에서 분명히 식별 가능해야 함

### 7.5 배경 활용
배경은 완전한 흰색보다 아주 옅은 블루-그레이가 적합하다.  
이 미세한 차이로 공간 전체의 온도와 해저의 차분한 분위기를 만든다.

---

## 8. 타이포그래피

### 8.1 원칙
이 사이트의 고급스러움은 절반 이상이 타이포그래피에서 나온다.  
좋은 타이포는 "읽기 쉬움", "위계", "정서"를 동시에 만든다.

### 8.2 폰트 방향
- 웹폰트: Geist (CDN via jsdelivr, variable weight 100-900)
- 한글 fallback: system-ui / Apple SD Gothic Neo
- 영문 타이틀과 한글 본문이 함께 있을 때도 리듬이 깨지지 않아야 함

### 8.3 타입 스케일
권장 스케일:

- Hero Title: `48 ~ 64px / 600`
- Page Title: `32 ~ 40px / 600`
- Section Title: `22 ~ 28px / 600`
- Card Title: `18 ~ 20px / 600`
- Body Large: `18px / 400`
- Body Default: `16px / 400`
- Meta: `13 ~ 14px / 500`
- Caption: `12px / 500`

### 8.4 line-height
- Hero / 큰 제목: `1.1 ~ 1.2`
- 본문: `1.6 ~ 1.75`
- 작은 설명: `1.5`

### 8.5 타이포 운용 규칙
- 제목은 무게로 강조하고, 색은 최대한 절제
- 같은 계층 제목의 크기는 화면 전체에서 일관되게
- 본문 폭이 너무 넓지 않아야 가독성이 유지됨
- bold 남발 금지
- 긴 문단은 3~4줄 단위로 적절히 호흡

## 9. Surface / Card / Depth 시스템

### 9.1 카드 기본 원칙
카드는 UI 장식이 아니라 **정보의 컨테이너**다.  
따라서 카드마다 개성이 달라지면 안 되고, 같은 의미의 카드에는 같은 문법을 유지해야 한다.

### 9.2 카드 기본 스펙
- 배경: Surface
- border: 1px solid Border
- radius: `20 ~ 24px`
- shadow: 매우 약하게
- padding: `20 ~ 28px`

### 9.3 카드의 종류
- Scene Card
- Question Card
- Response Card
- Highlighted Sentence Card
- Learner Card
- Collaboration Unit Card
- Summary Card

### 9.4 카드 간 계층
- Scene Card: 가장 기본
- Question Card: 더 조용하고 여유 있는 카드
- Response Card: 더 단순하고 플랫한 카드
- Summary Card: 요약과 안내 중심, 텍스트 비중 높음

### 9.5 고급스러운 깊이감 만들기
깊이감은 아래 순서로 만든다.

- 배경 톤 차이
- border 명도 차이
- 여백 차이
- blur / material
- 마지막으로만 shadow

## 10. 네비게이션 가이드

### 10.1 글로벌 네비게이션
구성:
- 로고
- 여정
- 기록
- 챌린지
- Learner
- 가이드
- 검색
- 기록 남기기 CTA

### 10.2 네비 디자인 원칙
- 얇고 조용해야 한다
- sticky 가능
- 배경은 투명 또는 약한 material
- 메뉴 수평 간격은 넉넉하게
- 현재 위치는 과한 색보다 underline-less 강조 방식 사용

### 10.3 모바일 네비
- 햄버거 메뉴 허용
- 하단 탭바는 사용하지 않음
- 검색과 기록 CTA는 우선순위 유지

## 11. Hero 가이드

### 11.1 역할
Hero는 제품을 설명하는 공간이 아니라, **현재 사용자를 정확한 정서 상태로 데려가는 공간**이다.

### 11.2 구성
- Eyebrow
- 큰 타이틀
- 짧은 설명
- CTA
- 배경 visual

### 11.3 비주얼 원칙
- 직접적인 해양 일러스트 사용 금지
- 수면 아래 빛의 층위, 푸른 안개, 깊이감 있는 gradient 활용
- 사진을 쓰더라도 디테일보다는 분위기 중심
- 텍스트 가독성 최우선

### 11.4 카피 톤
- 짧고 선명하게
- 과도한 브랜딩 슬로건 금지
- 문학적이되 모호하지 않게

---

## 12. Journey Strip / Timeline 가이드

### 12.1 역할
Journey Strip은 사이트의 핵심 구조다.  
한눈에 현재 위치와 전체 흐름을 보여줘야 한다.

### 12.2 시각 문법
- 각 Stage는 capsule 또는 세로 기둥 형태
- 현재 Stage는 진한 톤 + 약한 glow
- 과거는 채도 낮게
- 미래는 outline 위주
- Stage 간 간격은 균형감 있게

### 12.3 인터랙션
- hover 시 설명 노출
- click 시 Stage 상세 이동
- 모바일에서는 세로형 스택 또는 horizontally scrollable strip

### 12.4 주의점
- 지나치게 game-like한 progress UI 금지
- 퍼센트 진행률 과장 금지
- 현재 위치는 명확하되 경쟁적 느낌이 없도록

## 13. 기록 카드 가이드

### 13.1 Scene Card
포함 요소:
- 제목 또는 첫 문장
- 작성자
- Stage
- 개인 / 챌린지
- Note / Article
- 질문 여부

디자인 원칙:
- 너무 많은 정보로 카드가 무거워지지 않게
- 첫 문장이 좋은 요약이 될 수 있으면 제목보다 첫 문장을 크게
- hover 시 미세한 상승만 허용

### 13.2 Question Card
질문이 가장 크게 보이게 해야 한다.

권장 구조:
- 작은 라벨: `남겨둔 질문`
- 질문 문장
- 질문 방향
- 작성자 / 문맥
- 응답 CTA

질문 카드는 일반 기록 카드보다 **여백이 더 크고 조용해야** 한다.

### 13.3 Response Card
응답은 말풍선이 아니라 **정리된 메모 카드**처럼 보여야 한다.

포함 요소:
- 응답 유형 chip
- 작성자
- 본문
- 관련 기록 링크

좋아요/추천/수치 금지

### 구조

- 남긴 이유 한 줄
- 남긴 사람
- 원문 링크

### 디자인 원칙
- quote mark를 과하게 쓰지 않아도 됨
- 텍스트를 크게 보여주되, 정보 카드처럼 안정감 있게
- decorative quote art보다 타이포 자체로 해결

## 15. Learner 카드 가이드

### 역할
사람을 보여주되, 프로필보다 질문이 먼저 보이게

### 구조
- 이름
- 현재 질문
- 최근 기록 한 줄
- 현재 Stage
- 협업 흔적(있을 때만)

### 디자인 원칙
- 아바타는 보조 정보
- 카드 제목보다 질문이 시선의 중심
- "사람 소개 카드"처럼 보이지 않게

## 16. Collaboration Unit 카드 가이드

### 역할
실제 협업이 생긴 뒤에만 등장하는 카드

### 구조
- 이름
- 상태
- 현재 질문
- 최근 장면
- 관련 Challenge/Stage

### 디자인 원칙
- 팀 로고나 장식보다 질문 중심
- "프로젝트 카드"보다 "집단적 탐색 카드"처럼 보여야 함

## 17. 폼 / 에디터 가이드

### 17.1 에디터 기본 원칙
- distraction-free
- 쓰는 흐름 방해 최소화
- 메타 정보는 상단에 모으되 압박감 없게

### 17.2 입력 요소
- 입력창 radius는 cards보다 약간 작게
- border는 얇게
- focus 시 semantic blue 또는 deep tone
- textarea는 line-height 충분히
- placeholder는 안내형 문장

### 17.3 질문 입력 영역
질문 입력은 본문과 다르게 보여야 한다.

- 다른 배경 톤
- 작은 라벨
- 질문의 중요성이 느껴지되 과장되지 않게

### 17.4 Visibility / 응답 선호도 선택
- segmented control 또는 chip group 권장
- 옵션 수는 많지 않게
- 선택 상태는 분명하되 aggressive하지 않게

---

## 18. 검색 가이드

### 역할
통합 검색은 유틸리티이지만, 제품 정체성을 훼손하지 않아야 한다.

### 구조
- 검색창
- 최근 질문
- 최근 Learner
- 결과 탭
  - 기록
  - 질문
  - Learner
  - 문장

### 디자인 원칙
- autocomplete는 간결하게
- 검색 결과는 compact row 중심
- 검색 오버레이는 너무 기술 문서처럼 건조하지 않게

## 19. 알림 / 인박스 가이드

### 역할
인박스는 시끄러운 알림센터가 아니라, **흐름을 다시 이어주는 공간**이어야 한다.

### 구조
- 읽지 않음 / 전체
- 알림 리스트
- 각 알림은 맥락 중심 문장으로 구성

### 디자인 원칙
- 배지 과장 금지
- urgency tone 남발 금지
- 응답 알림도 "누가 남겼다"보다 "어떤 질문에 어떤 공명이 왔다"가 보이게

## 20. Collective Memory 가이드

### 역할
한 Stage를 공동 서사로 다시 읽는 화면

### 구조
- Hero
- 열린 질문
- 오래 남은 문장
- 대표 장면
- 이어진 기록
- 다음 Stage로 가져갈 질문

### 디자인 원칙
- 통계 보고서처럼 보이면 안 됨
- 감정적으로 과잉 연출하지 말 것
- 문장과 질문의 밀도를 높이고, 수치는 최소화
- 이 페이지는 "정리본"이 아니라 "되돌아보는 장면"이어야 함

## 21. 모션 가이드

### 허용
- fade-up
- subtle hover elevation
- slow background drift
- sheet / drawer 자연스러운 전환

### 금지
- bubble animation
- parallax 남발
- wave animation 남발
- bouncing microinteraction
- confetti / reward animation

### 원칙
모션은 존재를 느끼게만 하고, 시선을 잡아끌지 않는다.

## 22. 아이콘 / 일러스트 가이드

### 아이콘
- stroke 기반
- 단순하고 얇은 계열
- 크기 일관성 유지
- 텍스트 옆 보조 수단으로 사용

### 금지
- 3D 아이콘
- skeuomorphic 아이콘
- 만화적 잠수부 / 물고기
- 감정형 이모지 남발

### 일러스트
가능하면 최소화  
필요 시 abstract gradient / layered shapes 우선

## 23. 접근성 가이드

### 기본 기준
- 본문 최소 16px
- 충분한 색 대비
- 인터랙티브 요소 터치 타깃 넉넉하게
- 키보드 포커스 명확히
- reduced motion 지원
- 스크린리더 라벨 제공

### 포커스 상태
- outline 제거 금지
- focus ring은 충분한 두께와 명도차 필요
- hover와 focus를 같은 시각 효과로 처리하지 않기

### 텍스트
- 장식용 얇은 회색 텍스트 남발 금지
- 긴 본문은 line length 과도하게 넓지 않게

## 24. 카피 / 콘텐츠 디자인 가이드

### 문장 톤
- plain
- warm
- precise
- non-judgmental

### 지향
- `완성된 글이 아니어도 괜찮습니다`
- `이 질문을 다음 구간으로 가져갈 수 있습니다`
- `무엇이 남았는지부터 적어도 좋습니다`

### 지양
- `베스트`
- `인기`
- `정답`
- `상위`
- `완벽한 기록`

### UI 카피 원칙
- 버튼은 짧고 행동 중심
- 에러 문구는 plain language
- 빈 상태 문구는 다음 행동을 제안
- 강요보다 허가의 어조 사용

## 25. Admin 디자인 가이드

### 목적
운영자 콘솔은 public보다 정보 밀도가 높고 utilitarian해야 한다.

### 톤
- neutral
- calm
- efficient
- dense
- readable

### 구조
- 좌측 네비
- 상단 context bar
- main canvas
- optional inspector drawer

### 카드 / 패널
- public보다 radius 약간 줄이기
- border와 section divider 적극 사용
- dense table 허용
- 상태는 semantic badge로 표현

### 금지
- 감성적 Hero
- 과한 블루 테마
- decorative ocean graphics
- public 스타일의 large whitespace 남발

### 우선순위
- 빠른 스캔
- 빠른 편집
- 빠른 필터링
- preview
- bulk action

## 27. 품질 체크리스트

### 전반
- 같은 계층의 제목 크기가 일관적인가
- 여백 체계가 흔들리지 않는가
- Stage 톤이 명확히 구분되는가
- 해저 감성이 과하지 않은가
- 기록과 질문이 가장 먼저 보이는가

### 상세 화면
- 본문 읽기 폭이 안정적인가
- 질문 카드가 충분히 구분되는가
- 응답이 댓글처럼 보이지 않는가
- 이어진 기록의 관계가 읽히는가

### 홈
- Journey가 먼저 보이는가
- Current Dive가 숫자 대시보드처럼 느껴지지 않는가
- 열린 질문이 코호트의 존재감을 주는가

### Admin
- 정보 밀도는 높지만 답답하지 않은가
- 필터와 테이블이 빠르게 스캔되는가
- preview와 edit 흐름이 자연스러운가

### 접근성
- focus 상태가 선명한가
- contrast가 충분한가
- 모바일에서 터치 영역이 좁지 않은가
- 텍스트가 너무 작지 않은가
