# 사용자 플로우

> **구현 상태 안내**: 각 플로우에 구현 상태를 표시합니다.
> - `[구현됨]` — 해당 플로우의 핵심 경로가 구현됨
> - `[부분 구현]` — 일부 경로만 구현됨
> - `[미구현]` — 해당 기능이 아직 구현되지 않음
> - `[비활성화]` — 관련 라우트가 비활성화됨

## 플로우 1. 첫 방문과 구조 이해 [구현됨]

### 목표
사용자가 `divelog.page`가 무엇을 위한 공간인지 빠르게 이해한다.

### 시작 조건
- 사용자가 홈에 처음 진입함

### 흐름
- 홈 Hero를 본다.
- `질문하고, 만들고, 기록하는 아홉 달`이라는 메시지를 읽는다.
- `여정 활동` 섹션에서 최근 흐름을 읽는다.
- `최근 장면들`과 `남겨둔 문장`을 보며 이 공간이 결과보다 기록과 공명 중심이라는 것을 이해한다.
- `러너 스포트라이트`를 통해 사람과 질문의 흐름을 감각적으로 파악한다.
- `여정 보기` 또는 `기록 남기기`로 이동한다.

### 기대 결과
- 사용자는 이 사이트를 블로그나 SNS가 아니라, 여정 중심의 기록 공간으로 인식한다.

---

## 플로우 2. 첫 기록 작성 [구현됨]

### 목표
Learner가 부담 없이 첫 기록을 남긴다.

### 시작 조건
- Learner가 `기록 남기기`를 클릭함

### 흐름
- 기록 작성 시작 화면에서 `노트` 또는 `아티클`을 선택한다.
- 노트라면 본문과 Visibility를 입력한다.
- 아티클이라면 제목, 본문, Rhythm, Visibility를 입력한다.
- 필요 시 날짜 입력을 보완한다.
- 응답 선호도는 작성자 기본값으로 저장된다.
- Visibility를 `Draft`, `Private`, `Cohort`, `Public` 중 하나로 선택한다.
- 저장 또는 발행한다.

### 기대 결과
- 완성된 긴 글이 아니어도 기록을 남길 수 있다는 감각을 얻는다.
- 기록은 즉시 여정 구조 안에 배치된다.

---

## 플로우 3. 기록 끝에 질문 남기기 [구현됨]

### 목표
기록을 닫힌 결론이 아니라 열린 질문으로 마무리한다.

### 시작 조건
- Learner가 기록 작성 중이거나 수정 중임

### 흐름
- 기록을 먼저 저장하거나 발행한다.
- 기록의 details 화면으로 이동한다.
- `남겨둔 질문` 필드를 열어 질문을 입력한다.
- 질문 방향을 고른다.
- 메타데이터를 저장한다.

### 기대 결과
- 기록은 하나의 완결된 산출물이 아니라 다음 생각으로 이어지는 장면이 된다.

---

## 플로우 4. 다른 Learner 기록 읽기 [구현됨]

### 목표
다른 Learner의 기록을 읽고 공감과 연결을 얻는다.

### 시작 조건
- 홈, Stage, 기록 목록, Learner 상세 등에서 기록 카드를 열람함

### 흐름
- 기록 상세로 들어간다.
- 본문을 읽는다.
- 남겨둔 질문이 있는지 확인한다.
- Side rail 또는 본문 하단의 관련 기록과 문장을 본다.
- 필요 시 응답을 남기거나 문장을 저장한다.

### 기대 결과
- 사용자는 다른 사람의 기록을 평가 대상이 아니라, 함께 지나는 여정의 한 장면으로 읽는다.

---

## 플로우 5. 질문에 응답하기 [구현됨]

### 목표
댓글 평가가 아닌, 질문–응답 구조로 대화에 참여한다.

### 시작 조건
- Learner가 다른 Learner의 기록 또는 질문을 읽고 있음

### 흐름
- 남겨둔 질문 카드 아래 `응답하기`를 클릭한다.
- 응답 유형을 선택한다.
  - 공명
  - 질문
  - 연결
  - 제안
- 입력 프롬프트를 읽는다.
- 응답을 작성한다.
- 필요하면 관련 기록을 연결한다.
- Visibility를 확인하고 제출한다.

### 기대 결과
- 응답이 댓글처럼 보이지 않고, 기록을 이어 주는 행위로 인식된다.

---

## 플로우 6. 자기답변 남기기 [구현됨]

### 목표
Learner가 시간이 지난 뒤 자신의 질문에 다시 답한다.

### 시작 조건
- Learner가 이전에 남겨둔 질문이 있음

### 흐름
- Learner가 인박스, 내 공간, Learner 페이지에서 예전 질문을 발견한다.
- `나중에 내가 다시 답하기`를 선택한다.
- 자기답변 작성 화면으로 들어간다.
- 현재 생각, 달라진 점, 아직 남아 있는 질문을 적는다.
- 저장한다.
- 자기답변이 기존 질문과 연결된 상태로 노출된다.

### 기대 결과
- Learner는 자신의 변화와 생각의 이동을 시각적으로 확인할 수 있다.

---

## 플로우 7. 질문의 궤적 다시 보기 [구현됨]

### 목표
하나의 질문이 여러 Stage를 거쳐 어떻게 변했는지 되돌아본다.

### 시작 조건
- 같은 질문 thread에 여러 질문/자기답변이 존재함

### 흐름
- Learner 상세 또는 기록 상세에서 질문 thread를 연다.
- 처음 남긴 질문을 본다.
- 이후 붙은 응답과 자기답변을 읽는다.
- 다른 Stage에서 이어진 질문을 확인한다.

### 기대 결과
- 사용자는 글 수가 아니라 질문의 이동으로 자신의 아홉 달을 인식한다.

---

## 플로우 8. 협업이 아직 없는 상태에서 챌린지 기록 보기 [미구현]

### 목표
협업이 생기기 전에도 챌린지 페이지가 자연스럽게 동작한다.

### 시작 조건
- 특정 Challenge에 Collaboration Unit이 아직 없음

### 흐름
- 사용자가 챌린지 상세에 진입한다.
- 문제 정의와 현재 질문을 본다.
- 개인 챌린지 기록 목록을 본다.
- Collaboration Layer에서 `이 챌린지는 아직 개인 탐색 중심입니다` 안내를 본다.
- 개인 기록을 중심으로 탐색한다.

### 기대 결과
- 사용자는 협업이 없다고 해서 챌린지 페이지가 비어 있다고 느끼지 않는다.

---

## 플로우 9. 협업이 생긴 뒤 챌린지 흐름 읽기 [미구현]

### 목표
협업 발생 이후 질문과 장면이 Collaboration Unit 단위로 자연스럽게 연결된다.

### 시작 조건
- Challenge에 하나 이상의 Collaboration Unit이 연결됨

### 흐름
- 사용자가 챌린지 상세에 진입한다.
- Collaboration Layer에서 각 Unit 카드를 본다.
- 각 Unit의 현재 질문과 최근 장면을 읽는다.
- 특정 Unit 상세로 이동한다.
- 멤버, 최근 장면, 전환점, 회고를 읽는다.

### 기대 결과
- 협업이 생겨도 상단 구조를 흔들지 않고, 필요한 문맥 안에서만 자연스럽게 등장한다.

---

## 플로우 10. 남겨두고 싶은 문장 저장 [구현됨]

### 목표
좋아요 대신 공명을 남긴다.

### 시작 조건
- 사용자가 기록 본문을 읽고 있음

### 흐름
- 본문에서 인상 깊은 문장을 선택한다.
- `남겨두고 싶은 문장`으로 저장한다.
- 왜 남았는지 한 줄 적는다.
- 공개 범위를 고른다.
- 저장한다.

### 기대 결과
- 사용자는 평가가 아니라 공명의 방식으로 기록에 반응한다.
- 저장된 문장은 홈, Learner 페이지, Collective Memory에 재활용될 수 있다.

---

## 플로우 11. Quiet Check-in 남기기 [미구현]

### 목표
긴 기록이 아니어도 현재 상태를 남긴다.

### 시작 조건
- 특정 Stage를 지나는 중
- Learner가 짧게 상태를 남기고 싶음

### 흐름
- Stage 상세 또는 홈의 체크인 CTA를 클릭한다.
- 현재 상태를 가장 잘 설명하는 단어를 고른다.
- 한 줄 메모를 적는다.
- 저장한다.

### 기대 결과
- 기록 장벽이 낮아지고, Stage의 분위기 데이터가 쌓인다.

---

## 플로우 12. Stage 종료 후 Collective Memory 보기 [비활성화]

### 목표
하나의 Stage를 공동 서사로 다시 읽는다.

### 시작 조건
- 특정 Stage가 종료됨
- Collective Memory가 발행됨

### 흐름
- 현재 코드베이스에서는 해당 라우트가 비활성화되어 있어 진입하지 않는다.
- 사용자는 대신 Stage 상세와 기록 목록을 통해 종료된 구간을 다시 읽는다.

### 기대 결과
- 사용자는 Stage를 리포트가 아니라 공동 기억으로 경험한다.

---

## 플로우 13. 내 공간에서 Draft 정리 [구현됨]

### 목표
Learner가 미완성 기록을 다시 불러와 이어 쓴다.

### 시작 조건
- Learner가 저장만 해둔 Draft가 있음

### 흐름
- `내 공간`에 진입한다.
- Draft 목록을 확인한다.
- 특정 Draft를 선택한다.
- 이어서 편집한다.
- 필요 시 details 화면에서 질문과 응답 선호도를 수정한다.
- Private, Cohort, Public 중 원하는 범위로 발행한다.

### 기대 결과
- 미완성 기록이 버려지지 않고 자연스럽게 이어진다.

---

## 플로우 14. 검색으로 질문 탐색 [구현됨]

### 목표
특정 질문, 기록, Learner, 문장을 통합적으로 찾는다.

### 시작 조건
- 사용자가 검색을 사용하려 함

### 흐름
- 상단 검색을 연다.
- 키워드를 입력한다.
- 결과를 유형별로 본다.
  - 기록
  - 질문
  - Learner
  - 문장
- 원하는 결과를 선택해 이동한다.

### 기대 결과
- 사용자는 하나의 검색으로 서로 다른 객체를 넘나들 수 있다.

---

## 플로우 15. 인박스에서 응답 확인 [구현됨]

### 목표
새 응답이나 자기답변 리마인드를 조용히 확인한다.

### 시작 조건
- 사용자에게 알림이 생성됨

### 흐름
- 사용자가 인박스를 연다.
- 새 응답, 멘션, 참여자 추가, 다시 읽기 리마인드 알림을 본다.
- 알림을 클릭해 해당 기록 또는 질문으로 이동한다.
- 읽음 처리된다.

### 기대 결과
- 알림이 실시간성보다 맥락성을 갖고 작동한다.

---

## 플로우 16. 운영자가 Current Stage를 변경 [구현됨]

### 목표
운영자가 여정 구조를 정확히 반영한다.

### 시작 조건
- 새로운 Stage 시작 시점

### 흐름
- 운영자가 Admin > Stages에 들어간다.
- 기존 current Stage를 past로 전환한다.
- 새 Stage를 current로 지정한다.
- 홈과 여정 페이지에 반영되는지 확인한다.
- 필요 시 Stage 설명과 heroContent를 수정한다.

### 기대 결과
- Public 영역에 현재 여정 위치가 즉시 반영된다.

---

## 플로우 17. 운영자가 홈 큐레이션 업데이트 [구현됨]

### 목표
홈의 질문, 장면, 문장, Learner spotlight를 조정한다.

### 시작 조건
- 운영자가 홈 화면 노출을 조정하려 함

### 흐름
- Admin > Curation에 진입한다.
- 기록, 문장, 러너 중심의 큐레이션 목록을 확인한다.
- 필요한 항목을 pin/hide 한다.
- 홈 반영 상태를 미리본다.
- 저장한다.

### 기대 결과
- 홈은 단순 자동 피드가 아니라 운영자의 의도를 가진 에디토리얼 화면이 된다.

---

## 플로우 18. 운영자가 문제 응답 moderation [구현됨]

### 목표
비교, 조롱, 공격적 평가를 차단한다.

### 시작 조건
- 운영자가 플래그된 응답 또는 점검 대상 응답을 확인함

### 흐름
- Admin > Dialogue에 진입한다.
- 문제 응답 리스트를 본다.
- 원문 질문과 원문 기록을 함께 확인한다.
- 숨김, visibility 변경, note 기록 등의 조치를 취한다.
- Audit Log에 변경이 남는다.

### 기대 결과
- Dialogue Layer가 댓글 문화처럼 흐르지 않도록 유지된다.

---

## 플로우 19. 운영자가 Collective Memory 발행 [비활성화]

### 목표
Stage 종료 후 공동 기억 페이지를 완성한다.

### 시작 조건
- 특정 Stage가 종료되었고 자동 수집된 재료가 존재함

### 흐름
- Admin > Memories에 진입한다.
- 해당 Stage의 질문, 문장, 기록 후보를 검토한다.
- 대표 항목을 정렬하고 pin/hide 한다.
- 요약 문장을 작성한다.
- 다음 Stage로 가져갈 질문을 선택한다.
- 발행 범위를 정하고 publish 한다.

### 기대 결과
- Stage 종료 후 Collective Memory가 빠르게 완성되어 노출된다.

---

## 플로우 20. 운영자가 Collaboration Unit 생성 [비활성화]

### 목표
협업이 실제로 생긴 시점부터 자연스럽게 구조를 반영한다.

### 시작 조건
- 특정 Stage 또는 Challenge에서 협업이 시작됨

### 흐름
- Admin > Collaboration에 진입한다.
- 새 Collaboration Unit을 생성한다.
- 이름, 상태, 관련 Stage/Challenge를 입력한다.
- 멤버를 연결한다.
- 현재 질문을 입력한다.
- 저장한다.
- 챌린지 상세와 관련 Stage에서 해당 Unit이 노출된다.

### 기대 결과
- 협업이 생긴 이후에만 시스템 안에서 자연스럽게 등장한다.

---

## 플로우 21. Public Reader가 공개 기록 탐색 [구현됨]

### 목표
외부 사용자가 Public 기록을 읽는다.

### 시작 조건
- 비로그인 또는 외부 사용자 진입

### 흐름
- 홈 또는 검색에서 Public 기록에 접근한다.
- Public Visibility의 기록만 본다.
- Cohort 또는 Draft 범위 기록에는 접근하지 못한다.
- Learner 상세에서도 공개된 요소만 확인할 수 있다.

### 기대 결과
- 공개 범위 정책이 일관되게 유지된다.

## 플로우 22. Learner가 응답 선호도를 활용 [부분 구현]

> 응답 선호도 변경은 /logs/:recordSlug/details에서 가능. 기록 작성 시 선택 UI는 기본값 사용.

### 목표
대화의 방향을 스스로 조절한다.

### 시작 조건
- Learner가 기록을 작성하거나 수정함

### 흐름
- 응답 선호도에서 원하는 방식을 선택한다.
- 기록을 저장/발행한다.
- 기록 상세에서 응답 작성자는 이 선호도를 확인한다.
- 응답은 선호도에 맞춰 더 자연스럽게 형성된다.

### 기대 결과
- 기록자는 대인적 위험을 더 낮게 느끼고, 더 편하게 공개할 수 있다.

## 플로우 23. 운영자가 템플릿과 프롬프트를 갱신 [부분 구현]

> 어드민 템플릿 관리 구현됨. 기록 작성 시 템플릿 선택 UI 미구현.

### 목표
기록 UX가 Stage 성격에 맞게 진화한다.

### 시작 조건
- 특정 Stage 또는 Challenge 타입에 더 적절한 프롬프트가 필요함

### 흐름
- Admin > Templates에 진입한다.
- 새 템플릿을 만든다.
- 적용 맥락, 형식, Stage 타입을 연결한다.
- 활성화한다.
- 현재 구현에서는 어드민에서만 관리되고, 기록 작성 화면에는 바로 노출되지 않는다.

### 기대 결과
- 템플릿은 고정형이 아니라, 운영과 학습 흐름에 맞게 조정된다.

## 플로우 25. 권한 없는 사용자 접근 [구현됨]

### 목표
Visibility와 역할 정책이 일관되게 적용된다.

### 시작 조건
- 사용자가 접근 권한이 없는 기록/질문/관리 페이지에 접근 시도함

### 흐름
- 시스템이 대상의 Visibility와 사용자 권한을 검사한다.
- 접근이 허용되지 않으면 적절한 안내 화면 또는 로그인 유도 화면을 보여준다.
- 민감한 데이터는 노출되지 않는다.

### 기대 결과
- 접근 제어가 일관되고 예측 가능하게 작동한다.
