#### 2. Participant Notification Logic (Lines 201-221)
**Before**:
```typescript
const notified = new Set<string>();
for (const participant of participants) {
  if (participant.userId === auth.user.id) {
    continue;
  }

  await createNotification(context.cloudflare.env.DB, {
    recipientId: participant.userId,
    type: "participant_added",
    title: `${actorName}님이 기록에 함께하는 사람으로 남겼습니다`,
    content: record.title,
    recordId: record.id,
  });
  notified.add(participant.userId);
}
```

**After**:
```typescript
// Deliver participant notifications asynchronously via waitUntil
context.cloudflare.ctx.waitUntil(
  (async () => {
    for (const participant of participants) {
      if (participant.userId === auth.user.id) {
        continue;
      }

      await notify({
        d1: context.cloudflare.env.DB,
        actorId: auth.user.id,
        recipientId: participant.userId,
        type: "participant_added",
        title: `${actorName}님이 기록에 함께하는 사람으로 남겼습니다`,
        content: record.title,
        recordId: record.id,
        visibility: record.visibility,
      });
    }
  })(),
);
```

## Key Improvements

### 1. Centralized Service Usage
- ✅ All participant notifications now go through `notify()` service
- ✅ No direct `createNotification()` calls in route handlers
- ✅ Consistent error handling and logging via service

### 2. Idempotency (Dedupe)
- ✅ Service checks for existing notifications with same `(recipientId, type, recordId)`
- ✅ Re-saving the same participants does NOT create duplicate notifications
- ✅ Dedupe happens at DB level first, then in-memory cache as fallback

### 3. Draft Visibility Guard
- ✅ `visibility: record.visibility` passed to service
- ✅ Service skips notification creation if `visibility === "draft"`
- ✅ Draft records do NOT trigger participant notifications

### 4. Non-Blocking Delivery
- ✅ Wrapped in `context.cloudflare.ctx.waitUntil()`
- ✅ Notifications delivered asynchronously
- ✅ Main save action completes immediately
- ✅ Failures don't block user experience

### 5. Service Guards Applied
The `notify()` service applies these guards automatically:
- ✅ Self-notification prevention: `actorId === recipientId` → skip
- ✅ Draft guard: `visibility === "draft"` → skip
- ✅ Preference opt-out: recipient has `participant_added: false` → skip
- ✅ Dedupe: existing notification with same `(recipientId, type, recordId)` → skip
