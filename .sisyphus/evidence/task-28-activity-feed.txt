# T28: Activity Feed Component — Evidence

Created journey-level activity feed component and integrated into homepage.

## Files Created/Modified

- `getRecentActivity(d1, options)` function

## Design Decisions

1. **Journey-level aggregation**: No individual user names exposed
   - "N개의 새 기록이 남겨졌습니다" format
   - Complies with FRD: no "likes", no "popular", no comparison

2. **Time grouping**: Three periods for clarity
   - today: last 24 hours
   - this_week: 7 days (excluding today)
   - last_week: 14 days (previous week only)

3. **Quiet Depth styling**: 
   - bg-surface with border-border-subtle
   - text-text-secondary for summaries
   - Small emoji icons (no complex icon library needed)

4. **Korean text**: All UI text in Korean per AGENTS.md requirement

## Key Learnings

1. Activity feed uses aggregated counts, never individual user attribution
2. Time boundaries use Unix epoch seconds (consistent with DB schema)
3. Component uses simple emoji icons instead of complex icon library
4. Loader query runs after batch query to avoid blocking
