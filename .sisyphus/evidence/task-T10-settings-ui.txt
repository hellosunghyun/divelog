# T10: Settings UI for Per-Type Notification Opt-Out

## Task Description
Extend `/settings` page to show per-type notification toggles with Korean labels, persisted via `upsertNotificationPreferences`.

## Implementation Summary

### Changes Made to `app/routes/public/settings.tsx`

1. **Added imports**:
   - `getNotificationPreferences`, `upsertNotificationPreferences`, `NOTIFICATION_TYPES`, `NotificationType` from `~/db/queries/social/notificationPreferences.server.ts`

2. **Added `NOTIFICATION_TYPE_LABELS` constant**:
   - Maps each notification type to Korean title and description
   - All 7 types covered: response, reply, mention, participant_added, reminder, reread_reminder, stage_transition

3. **Updated loader**:
   - Calls `getNotificationPreferences(context.cloudflare.env.DB, auth.user.id)`
   - Returns `notificationTypePreferences` alongside existing `learner`

4. **Updated action**:
   - Parses form data for each notification type (`notif_${type}`)
   - Calls `upsertNotificationPreferences` to persist changes

5. **Updated component**:
   - Destructures `notificationTypePreferences` from `loaderData`
   - Added notification type toggles in "알림 설정" section after the existing email toggle
   - Uses same UI pattern as existing checkbox (p-4, rounded-xl, border, bg-surface-secondary/50)
   - Quiet Depth design: clean layout, no visual clutter

| Type | Title | Description |
