기록을 남기기까지 사용자가 거치는 화면을 순서대로 정리합니다.

### 1-1. 홈 (/) — 첫 인상

| | 데스크톱 | 모바일 |
|---|---|---|
| 스크린샷 | ![Desktop Home](screenshots/01-desktop-home.png) | ![Mobile Home](screenshots/06-mobile-home.png) |

**구성 요소** (위→아래):
1. **GlobalNav** — 로고, 여정/기록/챌린지/러너/가이드 링크, 검색, `짧은 메모` / `글 쓰기` CTA
2. **Hero** — "수면 아래, 기록이 깊어지는 곳" + 여정 보기 / 기록 남기기 버튼
3. **여정 타임라인** — 13개 Stage 수평 스크롤, 현재 구간(Challenge 1) 강조
4. **여정 활동** — 이번 주 / 지난 주 활동 요약 (기록 수, 질문 수, 응답 수)
5. **현재 구간 + 열린 질문** — 좌측에 Stage 요약 카드, 우측에 8개 열린 질문 그리드
6. **최근 장면들** — 9개 기록 카드 (제목, 본문 미리보기, 작성자, Stage 뱃지)
7. **남겨둔 문장** — 4개 인용 카드 (blockquote + 남긴 이유 + 원문 링크)
8. **러너 스포트라이트** — 4명 러너 (질문이 먼저 보이는 카드)
9. **하단 CTA** — "더 깊은 곳에서, 기록은 시작됩니다" + 기록 남기기 버튼
10. **Footer** — 네비 링크, 서비스 설명

**기록 쓰기 진입점**:
- 네비 우측: `짧은 메모` (ghost 버튼) + `글 쓰기` (primary 버튼)
- Hero: `기록 남기기` 버튼
- 하단 CTA: `기록 남기기` 버튼
- 열린 질문 카드: `응답하기` 버튼 → 해당 기록 상세로 이동
- 빈 상태: `질문 남기기`, `첫 기록 남기기` 등

**모바일 차이점**:
- 네비가 햄버거 메뉴로 축소 (글 쓰기 CTA가 숨겨짐)
- Hero 버튼이 세로 스택
- 기록 카드/질문 카드 1열 배치
- 여정 타임라인 수평 스크롤 유지

### 1-2. 기록 목록 (/logs) — 다른 사람의 기록 탐색

| | 데스크톱 | 모바일 |
|---|---|---|
| 스크린샷 | ![Desktop Logs](screenshots/02-desktop-logs.png) | ![Mobile Logs](screenshots/07-mobile-logs.png) |

**구성 요소**:
1. **헤더** — "기록" 제목 + "러너들이 남긴 탐구의 기록들" 설명
2. **포맷 탭** — 전체 / 노트 / 글
3. **필터 바** — Stage, 유형(개인/챌린지/협업), 리듬(순간/주간/스프린트/월간/구간회고/개인회고/자유)
4. **정렬 + 뷰 전환** — 최근 기록 / 오래된 기록, 그리드 / 타임라인 뷰

- 제목 (링크)
- 본문 미리보기 (~120자)
- 작성자 이름 (프로필 링크)

**모바일 차이점**:
- 필터 바가 세로 스택으로 변경
- 카드 1열 배치
- 뷰 전환 버튼 유지

### 1-3. 기록 상세 (/logs/:recordSlug) — 기록 읽기 + 대화 참여

| | 데스크톱 | 모바일 |
|---|---|---|
| 스크린샷 | ![Desktop Record](screenshots/03-desktop-record-detail.png) | ![Mobile Record](screenshots/08-mobile-record-detail.png) |

**구성 요소** (위→아래):
1. **메타 정보** — 포맷/유형 뱃지 + 제목 + 작성자 링크
2. **본문** — 기록 내용 (plain text 또는 Tiptap 렌더링)
3. **남겨진 질문** — 작성자가 남긴 질문들 (방향 라벨: 함께 생각해볼 질문 / 스스로에게 묻다)
   - 각 질문 아래에 자기답변 표시 (날짜 + 내용)
4. **응답 남기기 폼** — 응답 유형 선택 (공명/질문/연결/제안) + 연결할 질문 선택 + 내용 입력
5. **문장 저장하기 폼** — 남겨두고 싶은 문장 + 이유
6. **응답 목록** — 기존 응답들 (유형 뱃지 + 작성자 + 내용)
7. **연결된 기록** — 다른 기록과의 링크 (역참조 포함)
8. **남겨두고 싶은 문장들** — 다른 사용자가 저장한 문장들

**대화(Dialogue) 유형** (댓글이 아님):
| 유형 | 설명 | 색상 |
|------|------|------|
| 공명 | 이 기록에서 무엇이 남았는지 말합니다 | 기본 |
| 질문 | 더 듣고 싶은 지점을 엽니다 | |
| 연결 | 내 경험이나 다른 기록과 이어봅니다 | |
| 제안 | 다음 시도를 조심스럽게 제안합니다 | |
| 자기답변 | 자신의 질문에 스스로 답변합니다 (별도 UI) | |

### 1-4. 짧은 메모 쓰기 (/write/note) — 빠른 기록

| | 데스크톱 | 모바일 |
|---|---|---|
| 스크린샷 | ![Desktop Note](screenshots/04-desktop-write-note.png) | ![Mobile Note](screenshots/09-mobile-write-note.png) |

**구성 요소**:
1. **← 돌아가기** 링크 (/write로)
2. **제목** — "짧은 메모"
3. **설명** — "떠오르는 생각을 빠르게 남기세요."
4. **공개 범위** 드롭다운 — 코호트 공개 (기본값) / 전체 공개 / 임시저장
5. **구간** 드롭다운 — 현재 Stage 자동 선택 (Challenge 1), 변경 가능
6. **텍스트 입력** — textarea, placeholder: "무엇이 남았는지부터 적어도 좋습니다..."
7. **글자 수** — 0 / 50,000
8. **저장 / 취소** 버튼

**특징**:
- **제목 자동 생성**: 별도 제목 입력 없이, 본문 첫 줄에서 자동 추출
- **distraction-free**: 에디터 도구 없이 순수 텍스트만
- **현재 Stage 자동 선택**: 구간 드롭다운에 "(현재)" 표시
- **허가형 placeholder**: "무엇이 남았는지부터 적어도 좋습니다..."

**모바일 차이점**:
- 레이아웃 거의 동일 (1열이므로 자연스러운 반응형)
- 드롭다운 2개가 같은 줄에 배치

### 1-5. 글 쓰기 (/write/article) — 본격 기록

| | 데스크톱 | 모바일 |
|---|---|---|
| 스크린샷 | ![Desktop Article](screenshots/05-desktop-write-article.png) | ![Mobile Article](screenshots/10-mobile-write-article.png) |

**구성 요소**:
1. **← 돌아가기** 링크
2. **제목** — "글 쓰기"
3. **설명** — "여유롭게 탐구의 기록을 남기세요."
4. **공개 범위** + **구간** 드롭다운 (노트와 동일)
5. **제목 입력** — 필수(*), placeholder: "제목을 입력하세요"
6. **Tiptap 리치 에디터**:
   - **툴바**: 블록 타입(본문/제목1-3/인용구/코드블록), 굵게, 기울임, 밑줄, 취소선, 인라인코드, 링크, 형광펜, 체크리스트, 표, 이미지
   - **본문 영역**: contenteditable
   - **글자 수 표시**: 0 자
7. **템플릿 선택** — 9개 옵션:
   - 템플릿 없이 시작 (기본값)
   - 오늘의 한 줄
   - 이번 주 메모
   - 스프린트 기록
   - 구간 회고
   - 개인 회고
   - 함께하는 탐색 기록
   - 자유 형식
   - 챌린지 일지
8. **저장 / 취소** 버튼

**모바일 차이점**:
- 에디터 툴바가 수평 스크롤 (좁은 화면에서 아이콘 일부 잘릴 수 있음)
- 템플릿 드롭다운 전체 너비

## 2. 기록 쓰기 전체 플로우

```
사용자 진입
  │
  ├─ 네비 "짧은 메모" 클릭 ──→ /write/note ──→ 텍스트 입력 ──→ 저장
  │
  ├─ 네비 "글 쓰기" 클릭 ──→ /write/article ──→ 제목+본문 입력 ──→ 저장
  │
  ├─ Hero "기록 남기기" 클릭 ──→ /write ──→ 노트/글 선택 ──→ 입력 ──→ 저장
  │
  └─ 기록 상세에서 "응답하기" ──→ /logs/:slug ──→ 응답 유형 선택 + 입력 ──→ 등록
```

### 인증 요구사항

| 동작 | 인증 | 검증 |
|------|------|------|
| 홈, 기록 목록, 기록 상세 읽기 | 불필요 | - |
| 기록 쓰기 (노트/글) | 필수 | `requireVerified` (isVerified=true) |
| 응답 남기기 | 필수 | `requireVerified` |
| 문장 저장 | 필수 | `requireAuth` |

미인증 사용자가 /write 접근 시:
1. adakrpos_session 쿠키 있음 → 인증 재시도 페이지 (5회 자동 폴링)
2. 쿠키 없음 → `ada-kr-pos.com/login?callbackUrl=...` 리다이렉트

## 3. 기록 작성 후 경험

저장 성공 후 기록이 표시되는 곳:

| 위치 | 설명 |
|------|------|
| `/logs` | 기록 목록에 최신순으로 표시 |
| `/logs/:recordSlug` | 기록 상세 페이지 생성 |
| `/` 홈 최근 장면 | 최신 9개에 포함 시 표시 |
| `/journey/:stageSlug` | 해당 Stage 페이지의 기록 목록 |
| `/me` | 내 대시보드의 기록 목록 |
| `/learners/:slug` | 내 프로필의 기록 목록 |

### 기록에 붙는 메타데이터

| 필드 | 값 | 설정 시점 |
|------|-----|----------|
| format | note / article | 작성 경로에 따라 자동 |
| type | personal (기본값) | 추후 챌린지/협업 연결 시 변경 |
| rhythm | free (기본값) | 편집 시 변경 가능 |
| visibility | draft / cohort / public | 작성 시 선택 |
| responsePreference | open (기본값) | 편집 시 변경 가능 |
| stageId | 현재 Stage | 작성 시 선택 (자동 기본값) |

## 4. 현재 상태 관찰

### 잘 되어 있는 것

1. **2가지 쓰기 경로 분리**: 짧은 메모(빠른 기록)와 글 쓰기(본격 기록)가 명확히 나뉨
2. **허가형 카피**: "무엇이 남았는지부터 적어도 좋습니다...", "완성된 글이 아니어도 괜찮습니다"
3. **진입점 다양**: 네비, Hero, 하단 CTA, 빈 상태 등 여러 곳에서 기록 쓰기 접근 가능
4. **현재 Stage 자동 선택**: 구간 드롭다운에서 현재 Stage가 기본 선택됨
5. **Dialogue Layer**: 단순 댓글이 아닌 5가지 응답 유형으로 대화 구조화
6. **자기답변**: 자신의 질문에 스스로 답변할 수 있는 구조
7. **리치 에디터**: 글 쓰기에서 Tiptap 기반 서식 도구 제공
8. **템플릿**: 9가지 작성 템플릿으로 시작 부담 감소
9. **문장 저장**: 다른 사람의 기록에서 인상 깊은 문장을 저장 가능

### 피드백 관찰 포인트

1. **자동 저장 없음**: 긴 글 작성 중 이탈 시 내용 유실 위험 (의도적 배제이나 UX 리스크)
2. **노트 작성 시 제목 없음**: 자동 생성이지만 사용자가 인지하기 어려울 수 있음
3. **글 쓰기 에디터 로딩**: Tiptap 확장이 14개 이상, 초기 로드 시 콘솔 에러 발생 가능
4. **모바일 에디터 툴바**: 좁은 화면에서 아이콘이 잘리거나 스크롤 필요
5. **응답 선호도 설정 없음**: 작성 시점에 responsePreference를 설정할 수 없음 (편집에서만)
6. **질문 입력 없음**: 작성 시점에 질문을 함께 남길 수 없음 (기록 상세에서만)
7. **임시저장 후 찾기**: draft 상태 기록은 /me에서만 접근 가능
8. **모바일 네비에서 글쓰기 CTA 숨김**: 햄버거 메뉴 안에만 존재

## 6. 기술 참고

- **에디터**: Tiptap 3.20.1 + 20개 이상 확장 (굵게, 기울임, 밑줄, 취소선, 인라인코드, 링크, 형광펜, 체크리스트, 표, 이미지, 코드블록, 멘션, 기록참조, 콜아웃, 접기, 목차, 슬래시커맨드)
- **검증**: Zod (제목 1-200자, 내용 1-50,000자, article은 Tiptap JSON 필수)
- **인증**: `@adakrpos/auth` 외부 인증, `requireVerified` 미들웨어
- **저장 흐름**: 폼 submit → action에서 Zod 검증 → Drizzle ORM → D1 INSERT → redirect to /logs/:slug
- **이탈 방지**: `useUnsavedWarning` 훅 (beforeunload 이벤트)
